## 已核实的问题

- 原记录源帧 1451、60.3396 秒存在持球者真实检测：置信度约 .371，框 `[856,821,917,975]`。旧关联给 ID79，ByteTrack 没有输出此观测的确认 ID，ID218 位于 lost 列表；60.6729 秒出现新的 P425。这里不能仅归因于 YOLO 没检出，需检查跨帧匹配和待确认轨迹。
- 篮下多人交叉时有重复/局部人物框；场边坐着的人被长期续接。矩形 ROI 只检查脚点位置，不能识别上场身份。用户要求提高的上边界 .66 保留，不擅自改回 .70。
- 1920×1080 全帧以 imgsz=640 推理，人物在输入中较小。提高分辨率是待验证的方向，但还会增加场边检出与计算量，不能预先保证改善。

## 建议的整改顺序与判定方法

1. 固定篮下交叉、快速移动、横向移动、场边人员四类片段，逐人核查真实检测与 ID。分别记漏检、同人重复框、背景目标、换号和消失；减少 ID 总数不能单独判为变好。
2. 先改善跟踪输入：比较640/960/1280，逐项比较重复框抑制；评估球场多边形 ROI，保留远端球员并检查边线误排。只有看到重复框/漏检和场边混入减少，才能采用；不自动缩回用户指定的上边界。
3. 在相同检测上检查 ByteTrack 的匹配代价、分数融合、建轨迹门槛、丢失缓冲。重点复核60秒持球者及篮下交叉。每次只改变一个因素，防止增加缓冲后把另一个人续成旧 ID。
4. 检测连续、干净后仍频繁换号，再评估外观重识别（ReID：增加衣着等外观信息）或模型针对本场景微调。相似球衣/遮挡仍有局限，额外模型、数据和耗时需要单独验证，当前未实施。

整改目标是同一真实人物在可见片段中少丢失、少换号、少重复，不是“所有帧都有框”。需重新生成同片段 ID 对照视频并人工核查，达到用户认可后再交付 G2 验收。
